### 01. 项目定位

基于 OpenHarmony + ArkTS 原生开发，采用 MQTT over TLS 1.3 通信协议，结合 EMQX 消息中间件与 AES-256 应用层加密，构建安全可靠、软硬件协同的全栈智能家居控制系统。

### 02. 项目目标

- 确保系统原生兼容 HarmonyOS 全场景设备

```
┌─────────────────────────────────────┐
```

### 设备注册接口设计

```typescript
// 统一设备注册接口
interface DeviceRegistration {
  deviceId: string           // 设备唯一标识
  deviceName: string         // 设备显示名称
  deviceType: string         // 设备类型（light/ac/curtain等）
  manufacturer: string       // 制造商
  protocol: string           // 通信协议（MQTT/CoAP/Zigbee）
  topicConfig: TopicConfig   // MQTT主题配置
  capabilities: Capability[] // 设备能力列表

// 主题配置
interface TopicConfig {
  stateTopic: string    // 状态上报主题
  commandTopic: string  // 指令下发主题

}
```

## 第7页：亮点三 — 协议安全（10分）

### 全链路安全架构

```
┌────────────────────────────────────────────────────────────┐
│                     全链路安全架构                          │
├────────────────────────────────────────────────────────────┤
│  APP ←→ TLS 1.3 加密通道 ←→ EMQX ←→ TLS 1.3 ←→ 设备     │
│              ↓                    ↓                        │
│        AES-256 加密          AES-256 解密                  │
│              ↓                    ↓                        │
│        密钥安全存储          密钥安全存储                   │
└────────────────────────────────────────────────────────────┘
```

### 01. 传输层安全 (TLS 1.3)

- MQTT 通信固定 8883 加密端口
- 全链路 TLS 1.3 最新加密算法
- 双向证书认证，防止中间人攻击

### 02. 数据层安全 (AES-256)

- APP 下发控制指令前进行 AES-256 对称加密
- 报文到达设备端自动解密执行
- 即使泄露也无法破译原始指令

### 03. 密钥层安全

- AES 密钥安全存储于系统密钥库中
- 不在代码中硬编码
- 支持密钥定期轮换机制

## 第9页：双向状态同步机制

### 30ms 自动同步

```
┌─────────────────────────────────────────────────────────────┐
│                    双向状态同步机制                          │
├─────────────────────────────────────────────────────────────┤
│  鸿蒙APP                          Node.js模拟器             │
│     │                                    │                  │
│     │  ① 用户操控设备                    │                  │
│     │ ──────────────────────────────────→│                  │
│     │     MQTT: home/device/{id}/command │                  │
│     │                                    │                  │
│     │  ② 模拟器处理指令                  │                  │
│     │                                    │                  │
│     │  ③ 模拟器发布新状态                │                  │
│     │←──────────────────────────────────│                  │
│     │     MQTT: home/device/{id}/state   │                  │
│     │                                    │                  │
│     │  ④ 每 30ms 自动同步                │                  │
│     │←──────────────────────────────────→│                  │
│     │     双向状态检查（最后操作优先）    │                  │
└─────────────────────────────────────────────────────────────┘
```

### 最后操作优先原则

- 比较时间戳，以最后操作的状态为准
- 确保鸿蒙APP和Node.js模拟器状态始终一致
- 支持"刷新同步"按钮强制同步

## 第11页：室温模拟系统

### 智能温度控制

- **自定义室温**：输入框设置 10-40℃ 任意温度
- **空调制冷模拟**：空调开启时，温度自动下降
- **自然恢复模拟**：空调关闭时，温度缓慢趋向室外温度
- **实时显示**：室温、湿度、室外温度、空调状态

### 温度模拟逻辑

```javascript
// 空调制冷
if (空调开启 && 室温 > 设定温度) {
  温度 -= 0.5℃/秒  // 制冷速率
}

// 自然恢复
if (空调关闭) {
  温度 += 0.1℃/秒  // 趋向室外32℃
}
```
